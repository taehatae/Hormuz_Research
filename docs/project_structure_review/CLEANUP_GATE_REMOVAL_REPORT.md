# 프로젝트 정리 및 수동 승인 게이트 제거 결과

2026-11-08, Asia/Seoul. 이번 작업에서는 실제 기사·robots HTTP 요청, 본문 추출, 패키지 설치, 표본 재선정, Git commit/push를 하지 않았다.

## 1. 전체 조사

조사 시점 전체 파일 **7,549개**, 하위 폴더 **1,669개**, 논리 용량 **3,516,869,011 B**를 확인했다. 이 집계에는 조사 초기에 만든 목록·요약 파일 2개가 포함된다. 기본 권한에서 보이지 않던 vendor는 읽기 전용으로 재조사했으며 최종 누락/접근 오류는 0건이다.

프로젝트 자체 Python·노트북 44개, CSV/JSON/JSONL 스키마 1,057개를 조사했다. CSV는 스트리밍으로 행 수를 계산했고 대형 데이터를 통째로 메모리에 적재하지 않았다. 원본 CSV는 분석·재처리하지 않고 스키마/행 수와 보존 해시만 확인했다. vendor·바이너리·Git은 구조와 용도만 확인했다. `.env` 값은 읽거나 출력하지 않았다.

전체 파일의 크기·역할·Git 추적·정리 후 존재 여부는 [파일 목록](cleanup_gate_inventory.csv), 폴더 목록·용량·스키마·코드 import·노트북 셀 변수 의존성·중복 근거는 [조사 및 검증 자료](cleanup_gate_survey.json)에 있다. 크기가 작은 연구 텍스트의 동일 해시 그룹 94개를 확인했지만, 추출기별 비교 본문처럼 내용이 같아도 연구 역할이 다른 사본은 유지했다.

정리 후 재조사 시점에는 **7,516파일 / 1,665폴더 / 약 3.51GB**였고 누락 오류는 없었다. 이 수치에는 이번 조사·삭제 원장·보고서·작은 코드 복구본이 포함된다. 이번 정리 산출물을 제외한 동일 범위의 기존 프로젝트 자산은 7,547 → 7,511파일, 3,516,606,172 → 3,506,816,098 B로 약 **9.79MB 순감소**했다. 새 문서 자체의 최종 쓰기로 전체 논리 용량은 소폭 변할 수 있다. 삭제 파일 총량 9.98MB와 프로젝트 전체 순감소는 다른 수치다.

## 2. 실제 삭제

**파일 37개, 빈 폴더 4개, 9,977,483 B(약 9.98 MB)**를 삭제했다. 전체 경로·사전 SHA256·크기·Git 추적·삭제 이유·완료 상태는 [삭제 원장](cleanup_gate_deletions.csv)에 있다. 삭제 직전마다 정확한 경로와 해시·크기를 다시 대조했으며 재귀 삭제는 하지 않았다.

- 수동 정책 조사 도구: `scripts/review_pilot_access_policies.py`, `scripts/finalize_pilot_access_review.py`, 그 전용 테스트 및 `focused_access_followup_20261108_01/check_confirmed_terms.py`.
- 별도 승인 CSV/JSON: `domain_access_policies.csv`, `url_access_eligibility.csv`, `execution_approval_DRAFT.json`, `execution_approval_TEMPLATE.json` 및 폐기된 정책 조사 계획·체크포인트·감사 보고서.
- 폐기된 개발 실패 로그 6개. 최종 일반 회귀 근거는 유지했다.
- 잘못된 초기 순위로 생성한 v1의 재생성 가능한 분포 CSV 약 8.65MB. v1의 우선순위·SQLite·기사별 결과·상태 CSV는 보존했다.
- 중복 노트북 사본 1개. 정확히 같은 바이트가 Git 커밋 `8cad89a654d374e2face422946a94b7b5509f562`에 있고, 원래 57개 셀과 출력은 현재 노트북 및 코드 복구 ZIP에 모두 보존돼 있다.
- 과거 고정 200건 폴더의 사용하지 않는 빈 `html/`, `texts/`, `results/`, `robots/` 4개. 실제 자료가 있는 다른 실험의 동명 폴더는 건드리지 않았다.

명확하게 재생성 가능한 Python 캐시는 이번 조사에서 없었다. 대형 원자료·중간 연구 원장·라이브러리를 캐시로 간주해 삭제하지 않았다.

## 3. 폐기한 시스템과 보존한 제한 근거

`review_required → 수동 도메인 검토 → approved 파일 작성 → 실행` 시스템을 폐기했다. 이를 위해 정책 전용 도구의 import 참조와 승인 템플릿 생성 코드를 제거했다. `prepare_body_pilot_200.py`는 유일한 기존 표본 재현 기능이 있어 보존하되 승인 양식을 생성하지 않는다.

수집 제한의 사실은 `hormuz_2026_data/confirmed_access_restrictions.json`에 보존했다. 이는 허용 목록이나 수동 승인 대기표가 아니다. 명시적 금지 도메인 **5개**, 실제 제한 문맥이 있으나 조건이 불명확한 도메인 **3개**, 정확한 차단 URL **11개**, robots 관측 **172개**, HTTP 제한/오류 관측 **43개**가 포함된다. 원래 robots 파일, 원래 HTTP 요청 저널과 과거 잘못된 정책 조회 사건 기록도 유지했다.

## 4. 차단 위치와 변경

- 기존 `scripts/body_pilot_200.py`, `Gateway.policy()`, 변경 전 252~254행: `terms_reviewed`가 없으면 `site_terms_not_reviewed`, `allowed`가 없으면 차단, `evidence`가 없으면 검토로 중단했다.
- 기존 `validate_approval()`와 `main()`의 `--approval-file`/approved/승인자·시각·정확히 200개 조건을 제거했다. 모듈의 CLI는 상태 조회 전용으로 남겨 중복 실수집 진입점을 없앴다. 실제 수집 진입점은 기존 노트북 하나다.
- 노트북 60번째 셀의 `run_notebook_body_collection()`에서 정책 CSV 읽기와 `final_policy_status == allowed`를 이용한 기본 차단 생성 코드를 제거했다. 확정 제한 자료만 기존 Gateway에 전달한다.

수정 후 흐름:

```text
기존 선정 URL
→ 확정 금지/구체적 미해결 제한 확인
→ DNS의 모든 IP 및 URL 안전성 검사
→ robots 규칙·응답·요청 간격 검사
→ 제한된 HTTP 요청·리디렉션·403/429 처리
→ CAPTCHA/로그인/페이월 검사
→ 저장 HTML에 Fundus·Trafilatura
→ 단일 관리자 저장·재개
```

사전 검토 기록이 없다는 이유만으로 막거나 이를 승인으로 표시하지 않는다. 실제 제한·불명확한 robots·구체적 미해결 접근 조건은 계속 차단/보류한다. `human_review_required` 등 추출 품질 검토 표시는 승인 게이트와 다른 기능이므로 유지했다.

## 5. 기존 표본과 상태

기존 200건 큐, 원본/후보 CSV, 누적 우선순위, 모든 SQLite·상태 CSV·실제 HTML·본문·평가 결과는 변경하지 않았다. 노트북의 원래 57개 셀과 출력도 그대로다. 모듈 변경에 맞춰 `pilot_lock.json`의 실행 코드 SHA256만 갱신했으며 입력 큐·설정의 고정 해시는 유지했다.

수동 게이트 때문에 남았던 과거 review 행을 이번 작업에서 수정하지 않았다. 다음에 사용자가 노트북 수집 셀을 실행할 때만, **실제 기사 HTTP를 시작하지 않았고 수동 검토 게이트만이 원인이었던 행**을 자동 접근 검사 대기로 전환한다. 이전 상태·전체 결과를 SQLite `state_transition_history`에 보존하고 시도 횟수를 초기화하지 않는다. approved로 일괄 변경하지 않으며, 실제 차단·확보 본문·요청 결과 불확실 행은 이 전환에서 제외한다.

## 6. Fundus 환경 차이

기존 `06_benchmark_extraction_results.csv`에는 Fundus `success` 5건, Trafilatura `success` 17건이 있으며 Fundus 버전은 `fundus==0.5.7`로 기록돼 있다. success는 당시 비어 있지 않은 추출 결과이며 전체 본문·최종 정답을 뜻하지 않는다.

과거 노트북 메타데이터에는 Python 3.12.10이 있으나 이것만으로 당시 성공 환경 전체를 확정할 수 없다. 현재 도구 런타임은 Python 3.14.4이며 Fundus가 설치돼 있지 않다. 이전 작업의 설치 실패 기록에는 fastwarc 빌드 준비 단계 오류가 있다. 이번에는 재설치·환경 변경·추출 테스트를 하지 않았으며 해결됐다고 보고하지 않는다. 기존 Fundus·Trafilatura 구현과 벤치마크는 보존했다.

## 7. 검증

- 연구 데이터 **396파일**의 전후 SHA256 동일, 예상하지 않은 유실·변경 0개.
- 남아 있는 프로젝트 Python **37개** 구문 검사 및 새 노트북 셀 구문 검사 통과. 기존 셀 57개·전체 셀 60개·저장 출력 유지.
- 삭제한 승인 CSV/JSON을 읽는 실행 코드·삭제 도구를 import하는 잔존 코드 없음.
- 모의 robots/정적 검사 **13항목** 통과. 미검토 상태가 자동 검사로 진행하며, robots Disallow·불명확 robots·403/429·사설 DNS·확정 제한은 계속 차단/보류함을 확인했다. 실제 DNS·HTTP·기사 추출은 0회다.
- 기존 관련 단위 검사 2건도 통과했다. 11개 보존 URL 각각이 DNS 전에 차단되는지 확인했으며, 새로운 테스트 모음이나 실제 본문 추출 테스트는 만들거나 실행하지 않았다.
- 기존 큐·상태·우선순위와 코드 잠금 검증 통과. 노트북 수집 셀은 실행하지 않았다. 저장된 예전 출력은 현재 변경 코드를 실행한 결과가 아님을 메타데이터와 안내 셀에 표시했다.

과거 보존 manifest·개발 스냅샷에는 이번에 의도적으로 삭제한 파일과 이전 코드 해시가 남아 있다. 역사적 참조이며 현재 실행 의존성이 아니다. 이를 숨기거나 기존 검증 결과를 현재 통과로 다시 쓰지 않았다. 삭제 원장과 현재 검증 자료를 함께 확인해야 한다.
